# Google sign-in setup (issue #10)

How to turn on the Google button. Nothing here is secret — every value below
ships inside a client — but each surface stays dark until it is set, so a
deployment (or CI, or a local checkout) with none of this configured simply
shows no Google button.

See the "Signing in with Google" section of the root `README.md` for what the
flow actually does; this file is only the wiring.

## 1. Create the OAuth clients

In the [Google Cloud console](https://console.cloud.google.com/apis/credentials),
in **one** project, configure the OAuth consent screen and then create three
OAuth 2.0 client IDs:

| Type | Needs | Used by |
| --- | --- | --- |
| **Web application** | Authorized JavaScript origin `https://smiling.social` (add `http://localhost:5173` for local dev) | the website **and** the Android app |
| **iOS** | The app's bundle id, `com.katsonsoftware.goodvibesonly` | the iOS app |
| **Android** | The package name `io.github.andrewkatson.positiveonlysocial` and the SHA-1 of the signing certificate (one per certificate: debug *and* release) | nothing directly — but Google refuses to issue a token without it |

The Android app really does use the **web** client ID: Credential Manager mints
the ID token addressed to that client. The Android client ID exists so Google
can check the calling app's signature.

## 2. Backend

Every client ID that may appear in a token's `aud` claim must be listed, comma
separated. This list is the whole trust boundary — anything not named here is
some other app's token and is rejected.

```
GOOGLE_OAUTH_CLIENT_IDS="<web-client-id>,<ios-client-id>"
```

The Android client ID is deliberately absent: Android's tokens carry the web
client ID as their audience.

Unset, `POST /user_index/login/google/` answers `google_sign_in_unavailable` for
every request, which is the state CI and local development run in.

No migration beyond `0033_positiveonlysocialuser_google_sub` is needed.

## 3. Website

Set at build time (see `website/deploy-web.sh`, which already forwards it):

```
VITE_GOOGLE_CLIENT_ID="<web-client-id>"
```

For local development put the same line in `website/.env.local`. Unset, the
Google Identity Services script is never even fetched.

## 4. iOS

Fill in the constant in
`ios/Positive Only Social/Positive Only Social/api/GoogleSignIn.swift`:

```swift
enum GoogleSignInConfig {
    static let clientID = "<ios-client-id>"
}
```

It lives in source rather than the Info.plist because the app's Info.plist is
generated by Xcode (`GENERATE_INFOPLIST_FILE`). Nothing else is required — the
flow uses `ASWebAuthenticationSession`, which intercepts its own redirect, so
the reversed-client-ID URL scheme needs no `CFBundleURLTypes` entry.

## 5. Android

Add to `~/.gradle/gradle.properties` (user-level, like the FCM identifiers — the
repo's `gradle.properties` is tracked in git), or pass `-PGOOGLE_WEB_CLIENT_ID=…`:

```
GOOGLE_WEB_CLIENT_ID=<web-client-id>
```

Note again: the **web** client ID, not the Android one.

## Verifying it works

1. The button appears on the login screen (and, on the website, the register
   page as well).
2. Signing in with a Google account that has never used the app creates one:
   the response carries `created_account: true` and a membership number, and the
   generated username comes from the email local part.
3. Signing in again with the same Google account lands on the same account,
   with `created_account: false`.
4. Signing in with a Google account whose address matches an existing password
   account links the two — after which *both* the password and Google work.
5. An account with two-factor authentication enabled is still asked for its
   code after the Google step.
